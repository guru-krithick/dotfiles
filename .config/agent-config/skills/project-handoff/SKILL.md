---
name: project-handoff
description: Prepare or refresh a repository handoff when asked to summarize a work session, update handoff documents, or make ongoing work ready for the next session.
---

Find the repository's existing handoff and documentation ownership rules. Update its canonical locations instead of creating another tracking system. If no files exist and the user only asked for a summary, provide the handoff in chat.

Verify the current branch, working-tree status, and recent relevant changes. Distinguish this session's edits from pre-existing work. Record the completed outcome, relevant files, exact verification results, unresolved decisions or blockers, and the next bounded task.

Keep local edits, local commits, remote pushes, applied migrations, and deployments as separate facts; verify any status you report. Include the date when recording operational state. Exclude credentials, environment dumps, and full logs.

Link to canonical requirements and TODO documents rather than copying them. Do not mark an item complete without evidence, convert proposals into approvals, or carry out a future task merely because it appears in the handoff. Preserve useful existing notes that still apply.
